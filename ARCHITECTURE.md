## 四、认证与权限架构

### 4.1 JWT 认证流程

```
┌──────────┐                     ┌──────────┐                     ┌──────────┐
│   客户端  │                     │   后端   │                     │  数据库  │
└────┬─────┘                     └────┬─────┘                     └────┬─────┘
     │                                │                                │
     │ 1. POST /api/token/            │                                │
     │    {username, password}        │                                │
     │───────────────────────────────▶│                                │
     │                                │ 2. 验证用户信息                 │
     │                                │───────────────────────────────▶│
     │                                │                                │
     │                                │◀───────────────────────────────│
     │                                │ 3. 生成JWT Token               │
     │ 4. 返回 {access, refresh, user}│                                │
     │◀───────────────────────────────│                                │
     │                                │                                │
     │ 5. 后续请求携带 Header:        │                                │
     │    Authorization: Bearer {access}                               │
     │───────────────────────────────▶│                                │
     │                                │ 6. 验证Token有效性              │
     │ 7. 返回受保护的数据             │                                │
     │◀───────────────────────────────│                                │
     │                                │                                │
     │ 8. Token过期后 POST /api/refresh/                                │
     │    {refresh}                   │                                │
     │───────────────────────────────▶│ 9. 返回新的access token        │
     │◀───────────────────────────────│                                │
     │                                │                                │
```

### 4.2 权限控制

| 权限类 | 说明 | 适用场景 |
|--------|------|----------|
| `AllowAny` | 允许任何人访问 | 公开接口（如药品搜索） |
| `IsAuthenticated` | 需登录 | 普通用户接口 |
| `IsAdminUserCustom` | 需管理员身份 | 用户管理、数据导入等 |
| `IsRegularUser` | 需普通用户身份 | 用户端特定功能 |

## 七、安全架构

### 7.1 安全措施

| 层面 | 安全措施 | 实现方式 |
|------|---------|---------|
| **认证** | JWT Token | djangorestframework-simplejwt |
| **密码** | 前端加密传输 | RSA + AES 混合加密 |
| **密码存储** | 哈希存储 | Django PBKDF2 算法 |
| **接口权限** | 角色控制 | 自定义权限类 |
| **SQL注入** | ORM防护 | Django ORM 参数化查询 |
| **XSS防护** | 内容转义 | Vue 模板自动转义 |
| **CSRF防护** | Token验证 | Django CSRF Middleware |
| **文件上传** | 类型/大小限制 | 后端验证 |

### 7.2 密码加密流程

```
前端输入密码
```

## 八、技术选型理由

### 8.1 为什么选择 Django + DRF？

| 优势 | 说明 |
|------|------|
| **快速开发** | 内置ORM、Admin、认证等，开发效率高 |
| **RESTful** | DRF提供完整的REST API支持 |
| **安全性** | 内置防护SQL注入、XSS、CSRF等 |
| **扩展性** | 丰富的第三方库生态 |
| **Python生态** | 便于集成数据分析（Pandas）和AI功能 |

### 8.2 为什么选择 Vue 3？

| 优势 | 说明 |
|------|------|
| **响应式** | Composition API，更好的代码组织 |
| **TypeScript** | 类型安全，IDE支持好 |
| **性能** | 虚拟DOM优化，加载速度快 |
| **生态** | Element Plus 组件丰富 |
| **工程化** | Vite构建工具，开发体验好 |

### 8.3 为什么选择 MySQL + Redis？

| 组件 | 用途 | 理由 |
|------|------|------|
| **MySQL** | 主数据库 | 成熟稳定、性能好、便于维护 |
| **Redis** | 缓存 | 高性能缓存、Session存储、消息队列 |

## 九、性能优化策略

### 9.1 后端优化

| 策略 | 实现方式 |
|------|---------|
| **数据库索引** | 在药品名、商品名、ATC代码等字段添加索引 |

| 策略 | 实现方式 |
|------|---------|
| **懒加载** | 路由组件按需加载 |
| **虚拟滚动** | 大数据列表使用虚拟滚动 |
| **图片优化** | 图片懒加载、压缩 |
